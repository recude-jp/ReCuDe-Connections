# 共通スタンプの運用手順（追加・差し替え・修正・廃止）

全テナント共通のオリジナルスタンプ（こまめ・ルミ・ルカなど）を、本番運用を始めたあとに追加・入れ替えるための手順。
仕組みの設計は [`SPEC.md`](../SPEC.md) の 5-4 を参照。

> コミュニティのスタンプ（管理 > スタンプ で、ルートコミュニティ・連携コミュニティごとに登録。管理 A2）と、会員のマイスタンプ（マイページから登録）は、この手順の対象外。どちらもアプリの画面から登録するため、デプロイは要らない。

## 仕組み（最初に知っておくこと）

| 場所 | 中身 | 編集するか |
|---|---|---|
| `stamps/packs.json` | パックの一覧と、スタンプパネルのタブの並び順・タブ名 | **する** |
| `stamps/{packId}/pack.json` | そのパックのスタンプ（ID・文言）とバージョン | **する** |
| `stamps/{packId}/webp/{stampId}.webp` | 配信する画像（320×320・透過WebP） | **する**（置き換える） |
| `stamps/{packId}/svg/`・`png/`・`gen_*.py` | 原稿・生成スクリプト（アプリは使わない） | 必要に応じて |
| `public/stamps/{packId}/{stampId}_v{version}.webp` | 配信用の画像 | しない（自動で作られる） |
| `src/app/core/utils/stamp-packs.generated.ts` | アプリが使うスタンプの一覧 | しない（自動で作られる） |

- `npm run stamps:sync` が `stamps/` を検査して、配信用の画像とアプリの一覧を作り直す。画像が変わったパックは `version` を自動で上げ、`pack.json` に書き戻す。
- 画像のファイル名にバージョンが入っているため、差し替えると**別のファイル名**になる。ブラウザやPWAのキャッシュに古い画像が残らない。
- メッセージには**スタンプのID（`packId`・`stampId`）だけ**が保存されている。
  - 画像を差し替えると、過去に送ったメッセージのスタンプも新しい絵に変わる。
  - IDを消すと、過去のメッセージでは「削除されたスタンプ」になる。
- デプロイ（`npm run deploy`）の最初に `npm run stamps:check` が走る。取り込み忘れがあるとデプロイが止まる。

## 守ること

1. **スタンプIDとパックIDは変えない・使い回さない。** 過去のメッセージがIDで画像を探すため。違う絵柄・違う意味のスタンプには新しいIDを付ける。
2. **スタンプやパックは消さずに「非表示」にする**（手順E）。消すと過去のメッセージが「削除されたスタンプ」になる。
3. **画像は 320×320 の透過WebP、1枚100KBまで**（60KB以下が目安）。文字の太さ・余白は既存のパックとそろえる。
4. **IDは英小文字・数字・`-`・`_` の40文字以内。** `custom`（マイスタンプ）と `tp-` で始まるID（コミュニティのスタンプ）は予約されているため、パックIDに使えない。
5. `public/stamps/` と `stamp-packs.generated.ts` は**手で編集しない**（次の `stamps:sync` で上書きされる）。

## 手順

どの作業も、最後に「[共通: 確認からデプロイまで](#共通-確認からデプロイまで)」を行う。

### A. 既存のスタンプの絵を差し替える（例: ルミを描き直した）

1. `stamps/{packId}/webp/{stampId}.webp` を新しい画像で上書きする（ファイル名＝スタンプIDは変えない）。原稿（svg・png）も合わせて更新しておく。
2. `npm run stamps:sync` を実行する。
   - 「画像の変更・スタンプの追加があったため version を 1 → 2 に上げます」と出る。
   - `pack.json` の `version` と `path` は自動で書き換わる。**自分で version を上げなくてよい。**

### B. 既存のパックにスタンプを追加する

1. `stamps/{packId}/webp/{新しいID}.webp` を置く。
2. `stamps/{packId}/pack.json` の `stamps` に `{ "id": "新しいID", "text": "文言" }` を追加する。パネルでは、この並び順に表示される。
3. `npm run stamps:sync` を実行する（パックの version が上がる）。

### C. 新しいパックを追加する

1. `stamps/{新しいpackId}/` を作り、`webp/` に画像を置く。
2. `stamps/{新しいpackId}/pack.json` を作る（既存のパックをコピーして直すと早い）。

   ```json
   {
     "packId": "yui",
     "name": "ゆい（共通スタンプ）",
     "version": 1,
     "stamps": [
       { "id": "hajimemashite", "text": "はじめまして" }
     ]
   }
   ```

3. `stamps/packs.json` の `packs` に `{ "packId": "yui", "tabName": "ゆい" }` を追加する。タブの並び順は、この配列の順番。
4. `npm run stamps:sync` を実行する。
5. `stamps/{packId}/README.md` に、キャラクターの説明・色・原稿の作り方を書いておく（既存のパックに合わせる）。

### D. スタンプの文言（`text`）を直す

1. `pack.json` の `text` を直す。文言は、画面を読み上げるときの代替テキストに使う（画像の中の文字とそろえる）。
2. `npm run stamps:sync` を実行する（画像が同じなら version は上がらない）。

### E. スタンプやパックを使えなくする（廃止）

消さずに、`hidden` にする。スタンプパネルからは消えるが、過去のメッセージではそのまま表示される。

- スタンプ単位: `pack.json` のそのスタンプに `"hidden": true` を付ける。
- パック単位: `stamps/packs.json` のそのパックに `"hidden": true` を付ける。
- `npm run stamps:sync` を実行する。
- 元に戻すときは `hidden` を外して、もう一度 `stamps:sync` を実行する。

どうしても消す必要がある場合だけ（誤って追加した直後で、まだ誰も送っていない場合など）、`pack.json`・`packs.json` から消して、`npm run stamps:sync -- --allow-remove` を実行する。
付けずに実行すると、「送信済みのメッセージでは『削除されたスタンプ』と表示されます」というエラーで止まる。

## 共通: 確認からデプロイまで

1. **取り込み**: `npm run stamps:sync`。エラーが出たら、内容に従って `stamps/` を直して再実行する。主なエラーは次のとおり。
   - 画像がない
   - WebPではない
   - 320×320ではない
   - 100KBを超えている
   - IDの形式が違う・重複している
   - スタンプやパックが消えている
2. **差分の確認**: `git status` と `git diff` で、変わったファイルを確認する。
   - 差し替えの場合は、`public/stamps/{packId}/` の古い `_v{旧版}.webp` が消え、新しい `_v{新版}.webp` ができている。
   - `pack.json` の version と、`stamp-packs.generated.ts` も変わっている。
3. **画面で確認**（Emulator、`npm start`）:
   - トークのスタンプパネルで、タブ・並び順・絵が正しいこと。タブを切り替えて全部のスタンプを表示する。
   - 追加・差し替えたスタンプを1つ送り、トークと一覧（「スタンプ」）に正しく出ること。
   - 差し替えの場合は、以前に送ったそのスタンプが新しい絵で出ること。
   - 画面が古いままのときは、`npm start` を止めて起動し直す。`stamp-packs.generated.ts` を新しく作った直後などは、開発サーバーが変更に気づかないことがある。
4. **コミット**: `stamps/`、`public/stamps/`、`src/app/core/utils/stamp-packs.generated.ts` をまとめてコミットする。
   - 例: `スタンプ: ルミを描き直し（v2）`
5. **確認用環境・本番へのデプロイ**: `npm run deploy`。
   - 最初に `stamps:check` が走る。取り込み漏れがあれば、ここで止まる。
6. **本番での確認**: 本番の画面でスタンプパネルを開き、新しい絵が出ることを確かめる。
   - 開いたままの端末は、次にアプリを読み込んだときにPWAのサービスワーカーが新しい版に更新する。すぐに確かめたいときは、ページを2回読み込み直す。

## 元に戻したいとき（ロールバック）

スタンプの変更のコミットを `git revert` して、`npm run stamps:check` が通ることを確かめてから `npm run deploy` する。

- 版を戻すと、配信用の画像も前のファイル名（`_v{前の版}`）に戻る。キャッシュの問題は起きない。
- 新しい版で追加したスタンプが送信済みの場合、戻すと、そのメッセージは「削除されたスタンプ」になる。避けたいときは、戻す代わりに、そのスタンプを `hidden` にする変更をデプロイする。

## よくある質問

- **version は自分で上げるべき？** 上げなくてよい。`stamps:sync` が、配信済みの画像と比べて変わっていれば上げる。自分で上げた場合は、その番号がそのまま使われる。
- **PNGしか手元にない。** アプリはWebPだけを使う。原稿の生成スクリプト（`gen_*.py`）でWebPも書き出すか、変換ツールで 320×320 の透過WebPにしてから `webp/` に置く。
- **テナントごとに違うスタンプを出したい。** この手順ではできない（全テナント共通）。管理画面の「スタンプ」で、コミュニティのスタンプとして登録する（デプロイは要らない）。
